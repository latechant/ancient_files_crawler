## 二、执行时间线

### 阶段 1（09-14）：实体下载与归档
1. 建立 `源文件夹/`（整本原件 + 散篇）与 `最终提交版本/`（分卷文本）两级目录。
2. **整本下载**：
   - `大清会典图.djvu`（Wikimedia Commons，CADAL/清华大学藏本，102 页 / 5.5 MB，公有领域）
   - `青海大通上孙家寨古代居民mtDNA遗传分析.pdf`（中科院《人类学学报》2013年32卷2期，15 页 / 1.5 MB，**含文字层**）
   - 布顿佛教史藏文全文（大谷大学官方 txt.zip 解压，1.75 MB）
3. **维基文库分卷抓取**：按 `卷NN.txt` 逐卷落盘，实现**断点续跑**（已存在文件跳过）与请求间隔控制，
   覆盖《唐大诏令集》111 卷、《金华黄先生文集》44 卷、《震泽集》38 卷、《中庵集》20 卷、《定斋集》20 卷。
4. **散篇采集**：9 个 `<书名>_散篇/` 目录（每日诗词 2 篇、搜韵、数字藏经洞 P.T.1297、韩国国史编纂委员会仁祖实录卷之一、维基文库 4 篇）。
5. 产出 `下载记录.csv`（263 行，含大小与 SHA256）、`散篇索引.csv`（244 行）。

### 阶段 2（09-14）：PDF 章节拆分
1. 清点 `源文件夹`，确认真正的 PDF 只有 1 个；`大清会典图.djvu` 为 DjVu 影像容器，非 PDF。
2. **关键排查**：`pdftotext` 默认参数提取时**汉字全部为空**（拉丁字母正常），形似"无文字层"；
   加 `-enc UTF-8` 后汉字完整取回（5,326 字 / 0 替换符）。**根因为默认按 Latin1 输出丢弃 CJK 码位，并非缺文字层**，
   故**全程未启用 OCR**。
3. 用 PyMuPDF 独立提取一遍与 pdftotext 结果交叉验证，两者一致。
4. 无书签、无目录页 → 依据正文标题行定位章节边界，按论文真实章节拆分（**未套用"卷一/卷二"模板**）：
   `0_题名与摘要` / `1_简介` / `2_材料与方法` / `3_结果` / `4_讨论` / `5_结论` / `6_参考文献` / `7_英文摘要`。
5. 剔除版心页眉页脚与零宽字符；建立 `印刷页 = PDF页 + 203` 映射，每个 txt 头部标注双坐标。
6. 产出 `章节清单.csv`、`处理日志.md`、`问题清单.md`。

### 阶段 3（09-14）：链接核验与质检
1. 汇总 47 个唯一 URL 逐一访问，记录状态码、最终跳转、字节数。
2. **发现一类"状态码 200 但内容不可用"**：ctext 的 `wiki.pl` 链接中 4 个返回 200 却在响应体中是
   1425 字节反爬拦截页（"Checking the security of your connection…Web scraping of this site is in violation of our terms of service"）。
   → 改为**读取响应体判定内容性质**，不再只看状态码。
3. **方法学缺陷修正**：首轮对含中文路径的 URL 未做百分号编码，MediaWiki 误返回 404
   （`/wiki/中庵集_(四庫全書本)` 不编码 404/8028B，编码后 200/17548B）。**首轮全部非 ASCII 路径结果作废并重跑。**
4. 产出 `链接核验.csv`、`归档索引.csv`、`问题清单.csv`、`质检报告.md`。

## 五、已解决问题的对应方法

| 编号 | 问题 | 解决方法 |
|---|---|---|
| 阶段1 | 分卷抓取被限流中断 | **断点续跑 + 请求间隔**：已存在且非空的文件跳过，逐卷 sleep 2.5s，脚本可反复重跑直至补齐。曾因书名异体字（中菴集/中庵集）导致整本枚举为 0，改用维基文库 `list=search` 反查正确页面名后补齐 20 卷。 |
| 阶段2 | `pdftotext` 中文全空，形似"无文字层" | **加 `-enc UTF-8`**。默认编码按 Latin1 输出会静默丢弃 CJK。配合 PyMuPDF 双引擎交叉验证，确认为**排版编码问题而非缺文字层**，从而避免了一次不必要的 OCR 全流程。 |
| 阶段2 | 无书签/目录，章节边界不明 | 丢弃"卷次"模板，改用**正文标题行定位**，按论文真实章节拆分，并在每个 txt 头部标注 `印刷页/PDF页` 双坐标。 |
| 阶段3 | 状态码 200 但内容为反爬页 | **读响应体判定**：命中 `Checking the security` / `Web scraping … in violation` 特征串即判为"可访问但不适用于自动采集"，不因 200 而误计为可用成果。 |
| 阶段3 | 含中文 URL 被误判 404 | 对所有 URL 做**百分号编码**后再请求（`quote(unquote(path))`）。此缺陷曾使 `中庵集` 被误判，而该 URL 数分钟前才成功下载过 20 卷——正是这一矛盾促成复查。 |
| 阶段5/6 | 目录名不统一、结构参差 | 建 `重命名对照表.csv` 记录原名→新名，可回溯；建 `目录结构检查.csv` 逐目录核查三件套完整性；改造前先做 `_原件备份/`、`_来源说明备份/`。 |
| 阶段6 | 单人名下条目与项目产出对不上 | 提升到全组口径，用**两种口径交叉**（网址列有链接 / 项目有实质正文）核对 618 条，找出 20 条有正文但网址漏填、28 条有网址但未抓到。 |
| 全程 | 终端中文 GBK 乱码 | 沿用第一周方案：含中文结果**不直接打印**，写 UTF-8 文件后用 Read 读取。 |
| 全程 | 替换项需可追溯 | 统一格式：`【替换】原填：…；改为：…；依据：URL/版本；时间：YYYY-MM-DD`，共记录 6 条。 |

1. **实体产出完整**：255 个分卷 txt、248 个下载文件、115.2 MB 成果文件夹，目录命名统一且可回溯
