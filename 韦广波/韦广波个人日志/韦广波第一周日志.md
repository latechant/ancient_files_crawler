## 五、已解决问题的对应方法

| 编号 | 问题 | 解决方法 |
|---|---|---|
| P01 | 终端中文乱码 | 所有含中文的结果**不直接打印**，改为写入 UTF-8 文件后用 Read 工具读取；Python 脚本设置 `PYTHONIOENCODING=utf-8`。 |
| P02 | 缺 openpyxl/pandas | `python -m pip install openpyxl pandas`。xlsx 读写全程用 openpyxl。 |
| P03 | 清单为混合体、无 PDF 可下 | 先做**性质分类**（真古籍 / 方志报刊 / 考古档案器物），对 C 类明确标注"非独立图书"，说明步骤二/三不适用，而非强行套模板。 |
| P04 | 非书条目 | 判定规则增加一条：**题名为器物名、遗址名、地名、日期、档案类目者，直接判 none 并在备注写明属性**（如"《方鼎》为商周青铜器类名"）。 |
| P06 | 题名讹误/错位 | 备注列写明实际归属（如"《东方杂志到苗区去》实为《东方杂志》载文《到苗区去》"），不改动原表书名。 |
| P07 | 商业库垄断 | 建立明确规则：**商业库只记链接、不下载全文**；无合法免费源则填"无"，备注写明"全文在《全国报刊索引》，需机构订阅"。 |
| P08 | 版权期内著作 | 规则化为判 none 的条件之一，备注写明出版社与出版年以证其在版权期。 |
| P09 | 盗版/付费站污染检索结果 | 预设**黑名单**（网盘代找、加客服、VIP下载、z-lib、千千图书等），命中即剔除；要求所有 url 必须是检索工具真实返回过的，杜绝编造。 |
| P10 | 可下载原件极少 | 先用站点 API 探测真实下载地址（如 Wikimedia `imageinfo` 取原始文件 URL、中科院直链 PDF），再本地 curl 下载归档。 |
| P11 | 接口限流 | 内联调用受阻时**改用子代理并行**分散请求（4 代理 × 11 条），降低单点频次。 |
| P12 | ctext / 维基文库限流 | 实现**断点续跑 + 指数退避重试**：已存在的文件跳过，捕获 HTTP 429 后 `sleep(8×(n+1))` 重试最多 5 次，请求间隔 1.5s。首次 17 卷被拦，续跑补齐 27 卷。 |
| P14 | 扫描件无法自动分卷 | 改用**结构化全文源**（维基文库子页 wikitext → 纯文本），直接按卷生成，绕开版式识别问题。 |

## 七、结论

1. **网址核填（步骤一）已完成 154/154**，其中 30 条给出合法公开来源、121 条标"无"并写明原因、3 条待核，**无留空、无臆造**。
2. **合规底线全程守住**：未采用任何网盘、盗版、代找、付费墙绕过来源。
3. **步骤二、三仅对少数条目成立**：可下载原件 2 件已归档；分卷 txt 对 1 本书完成（44 卷）。其余条目因**本身不是书、或全文锁在商业库、或仍在版权期**，客观上无法执行"下载 PDF → 按卷 OCR"。
4. **最大瓶颈是 OCR 缺失**：若要继续攻影印本，须先装 OCR 引擎，且需预留人工校对与人工分卷的工作量。
